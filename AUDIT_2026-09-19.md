# Parsing2026 — 2026-09-19 engineering audit

This document records the second-stage hardening review performed against the
current `feat/multi-user-lzt-credentials` baseline.

## External API contract

The current LZT Market documentation states:
- category search endpoints are subject to a 20 requests/minute search limit;
- general GET traffic is limited to 300 requests/minute;
- non-GET traffic is limited to 30 requests/minute;
- `fast-buy` is the documented account purchase endpoint and accepts `price`
  and `balance_id`;
- `fast-buy` may return `retry_request`, which the API documentation says can
  be repeated up to 100 times.

The implementation therefore avoids probing undocumented legacy purchase paths,
uses only the documented Fast Buy route, and defaults to conservative request
pacing while still honoring server rate-limit headers.

## Security

Per-user LZT tokens remain encrypted at rest with Fernet and are bound to the
Telegram user ID. The audit added regression coverage ensuring ciphertext does
not contain the plaintext token and that missing encryption configuration fails
closed.

## Concurrency

The previous purchase strategy could launch multiple purchase HTTP requests in
parallel against several guessed endpoints. That creates an unnecessary race
for a one-item purchase. The audited strategy sends through exactly one documented Fast Buy route and does not fall back to alternate hosts. Purchase idempotency and the per-item lock are scoped by Telegram user, so two customers watching the same item do not suppress each other.

## Additional hardening completed

- Runtime purchase host is restricted to `https://api.lzt.market`.
- Balance and token verification no longer probe alternate LZT hosts and now use the adaptive rate-limit path.
- Credential replacement/revocation clears per-user in-flight autobuy state after queue shutdown.
- Docker Compose binds health/metrics to localhost instead of publishing the unauthenticated metrics endpoint externally.

## Validation still required

CI is necessary but not sufficient. Before enabling live autobuy:
1. run the complete Telegram runtime test;
2. connect a real LZT account with a valid Market API token;
3. verify balance and discovery against the live API;
4. execute a controlled live purchase test on an intentionally low-risk item;
5. verify duplicate prevention, cancellation and shutdown behavior;
6. review deployment secrets, backups and encryption-key recovery.

No live purchase was executed by this audit.
